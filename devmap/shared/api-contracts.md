# Shared API Contract

## Baseline

- Base path is `/api/v1`. Prototype `/api/...` routes are removed when migrated; no compatibility/dual API.
- JSON is camelCase; secure same-origin cookie auth; browser code never stores bearer material.
- OpenAPI generated by the backend is the transport authority. Generated TypeScript transport types are not hand-edited. Zod is for forms, frontend-only constraints and explicitly needed runtime validation.
- UUID IDs are opaque. Instants use ISO 8601; local dates `YYYY-MM-DD`; local times explicit wall-clock strings.

## Pagination

List request base: `cursor?`, bounded `limit?`, `sort?`, and feature-specific allowlisted filters. Cursor encodes the last item’s stable ordering tuple; clients do not interpret it. Ordering must be deterministic with a unique tie-breaker (normally ID).

```json
{ "items": [], "page": { "nextCursor": null, "hasMore": false } }
```

`nextCursor` is present only when another page is available and continues the same filter/order snapshot semantics. Filters/sorts are allowlisted per endpoint; there is no universal advanced query language.

## Generation workflow

Change backend DTO/endpoint → regenerate OpenAPI → regenerate TypeScript artifact → compile frontend and run contract/API tests → commit generated diff with the contract change. CI eventually checks drift, but provider/orchestration details remain under deferred `DEC-011`.
