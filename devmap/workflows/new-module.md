# New Module

1. Load progressive context and check the decision register.
2. Identify owning product sources and acceptance scenarios.
3. Define module boundary, ubiquitous terms, permissions, lifecycle, temporal rules, and events.
4. Confirm the existing pattern really fits; do not create a parallel architecture.
5. Follow `../04-module-implementation-loop.md` from domain through E2E.
6. Search before adding every reusable abstraction/dependency.
7. Complete `../checklists/module-checklist.md` and Definition of Done.
8. Update DevMap only when a reusable convention changed.

Stop if an unresolved conflict changes identity, lifecycle, API, ownership, or UI flow.
