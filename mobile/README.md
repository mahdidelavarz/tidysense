# TidySense Android app

The native Android app (Expo, React Native, TypeScript). The plan, stack and rules are in
[devmap/mobile](../devmap/mobile/README.md); sign-in follows [ADR-008](../devmap/decisions/ADR-008-native-client-authentication.md).

## First run on your phone

You need: Node (the same version as `/frontend`), Android Studio (for the Android SDK, platform tools and a JDK),
and an Android 10+ phone with **Developer options → USB debugging** on, on the same Wi-Fi as this PC.

1. Start the backend for the phone. It listens on the LAN over plain HTTP and shows the login code, so no SMS is
   sent:

   ```powershell
   ./dev.ps1 mobile-backend
   ```

   Windows asks whether to let `dotnet` through the firewall the first time: allow **private** networks.

2. Tell the app where that backend is. Find this PC's Wi-Fi address (`ipconfig`, "IPv4 Address") and create
   `mobile/.env.local` (git ignores it):

   ```text
   EXPO_PUBLIC_API_URL=http://192.168.1.20:5082/api/v1
   ```

   Without it the app uses `http://10.0.2.2:5082/api/v1`, which only works in the Android emulator.

3. Plug the phone in by USB, accept the "Allow USB debugging" prompt, then build and install the development
   build (the first build takes several minutes):

   ```powershell
   cd mobile
   npm ci
   npx expo run:android
   ```

   This is a development build, not Expo Go: the app needs native modules (secure storage, forced
   right-to-left) that Expo Go does not carry. After the first install, `./dev.ps1 mobile` starts Metro and the
   installed app reloads on save. Run `npx expo run:android` again only after a native change (a new native
   package or an `app.json` change).

4. Sign in with any phone number. A development build shows «کد آزمایشی ورود» with the code under the form.

## What to check on the phone (MOB-02)

- The whole screen is right to left, and Persian text is in Vazirmatn (not the phone's default font). The title
  «ورود یا ثبت‌نام» uses Noto Naskh.
- After sign-in the screen shows your number. Close the app fully and open it again: you are still signed in.
- The «پوسته» button switches device → dark → light; the colours change and survive a restart.
- «خروج» returns to the login screen.
- Optional: `maestro test maestro/login.yaml` runs the same path automatically
  ([Maestro](https://maestro.mobile.dev) must be installed).

Send screenshots of the login screen, the signed-in screen in light and dark.

## Everyday commands

| Command | What it does |
|---|---|
| `./dev.ps1 mobile-check` | typecheck, Biome lint, Jest |
| `./dev.ps1 mobile` | Metro for the installed development build |
| `npm run generate:api` | regenerates `src/shared/api/generated.ts` from `backend/openapi/TidySense.json` |

## Rules

- Add Expo and React Native packages with `npx expo install <name>`, never plain `npm install`, so versions
  match the SDK. If the Expo API is unreachable, `EXPO_OFFLINE=1 npx expo install <name>` uses the versions
  bundled with the CLI.
- `android/` is generated by `expo prebuild` / `expo run:android` and is not committed. Native settings belong
  in `app.json` or a config plugin, never in hand edits to `android/`.
- The session token lives only in `expo-secure-store` (`src/shared/lib/session.ts`). Never log it or put it in
  any other storage.
- All visible text goes through `src/shared/ui/AppText.tsx`, and colours come from `usePalette()`
  (`src/shared/ui/tokens.ts`, copied from `frontend/src/index.css`: change both together).
- Plain HTTP works only in a debug build. Release builds (MOB-12) talk to an HTTPS server.
